# Dynamic Starmap Surface 0.17.3 · Factorio 2.1.21 + Space Age

Обновление [старой карты пользователя](https://github.com/ArkadiPorovozov/custom-starmap) в существующем моде `dynamic-starmap`. Поверхность `dsm-space`, команды и runtime API сохранены. Реальные маршруты Space Age и метаданные PlanetsLib мод **не изменяет**.

## Камера, направления оборота и публичный API 0.17.3

- **ЛКМ по планете**: поверх каждой планеты на открытой карте держится кликабельная sprite-кнопка (`dsm-pbtn-*`, следует за телом и зумом); клик по ней (`on_gui_click`, цель — из `tags` кнопки) напрямую переносит удалённый просмотр на реальную поверхность планеты, при необходимости поверхность создаётся через `planet:create_surface()`. Это не зависит от `cursor_position`/`player.selected` mouse-событий в Remote View, которые в клиенте приходили пустыми. Наведение на кнопку показывает карточку планеты. Мировой клик по сущности/платформе (custom-input, поиск по расстоянию с радиусом захвата) сохранён как запасной путь. Переход подтверждается в чат; причины отказа пишутся в `factorio-current.log` с префиксом `[dynamic-starmap] LMB`. Программный фокус камеры внутри карты по-прежнему доступен через публичный API `focus`/`focus_platform`.
- Исправлен вылет при Shift+M на закрытии карты: перед переключением на персонажа камера Remote View переводится с `dsm-space` на поверхность **самого персонажа**; только затем вызывается `set_controller{type=character}`. Модельный тест имитирует проверку движка на совпадение поверхностей.
- При открытии удалённая камера ориентируется на `st.entities.star.position` и ещё раз фиксирует центр **до загрузки чанков следующего тика**; явное наведение на планету, платформу или координаты имеет приоритет. Нативная картинка Солнца остаётся entity — солнечного рендера нет.
- На data stage и в runtime появился `orbit_direction`: `1` = по часовой стрелке, `-1` = против. Для собственного вращения изображения отдельно есть `spin_direction`; он применяется при `tidal_lock=false`. Настройки индивидуальны для каждого тела, включая луны. Пример: `Map:update{name="nauvis",orbit_direction=-1,tidal_lock=false,spin_direction=-1,spin=3600}`.
- Публичный API расширен: определение **собственных объектов карты** в data stage, runtime-переопределения орбит, произвольный фокус камеры, сохраняющиеся текстовые/спрайтовые аннотации, состояния карты и данные объектов. Интерфейс вынесен в `scripts/public.lua`; полный справочник и рабочие примеры — в **[API.md](API.md)**. Это управление только модовой картой: реальные прототипы Space Age, маршруты и платформы не меняются.
- Добавлены модельные тесты перехода между поверхностями, центрирования камеры, пользовательского объекта, обоих направлений орбиты/вращения, аннотаций и восстановления орбит. В клиенте Factorio 2.1.21 результат ещё нужно проверить.

## Исправление отложенной очистки поверхности 0.17.2

- Из вашего `/dsm-hover-debug` после `/dsm-regenerate`: `bodies=0, sun=false, platforms=0`, хотя `clock` шёл. Причина: `LuaSurface.clear()` очищает поверхность **в конце тика**, а версии до 0.17.1 включительно пересоздавали объекты **в том же тике**; новые entity затем удалялись вместе с чанками.
- `/dsm-regenerate` теперь закрывает просмотр, запускает очистку и ждёт `on_surface_cleared`; только **после события** заново генерирует чанки и создаёт солнце, тела и платформы. Команда сначала сообщает о начале, а результат — после события. Повторные запросы открытия/перегенерации во время очистки блокируются, чтобы не создать тела раньше времени.
- Полностью убрано солнечное свечение через `rendering` из 0.17.1. **Солнце — только картинка entity** (`dsm-node-star`); орбитальные круги остальных тел по-прежнему рисуются через rendering. Радаров нет. `/dsm-hover-debug` дополнен состоянием ожидающей очистки и ошибкой сборки.
- Модельный тест теперь **специально откладывает удаление чанков и entity до события**, поэтому прежняя последовательность «`clear()` → немедленный `rebuild()`» больше не могла бы его пройти. Проверить настоящий клиент здесь нельзя; если после обновления объекты не появились, вызовите `/dsm-restore` и пришлите `/dsm-hover-debug` с логом `rebuilt:`.

## Возврат к прогрузке старого проекта 0.17.1 (сборка после очистки исправлена в 0.17.2)

- **Все радары удалены**, включая прототип `dsm-camera-radar`, стационарный радар и радары камер: звук радара исчезнет. Старые ссылки на них очищаются при обновлении сохранения.
- В `control/surface.lua` старого проекта `chart_surface_as_radar` запрашивала отсутствующие чанки на площади ±500 тайлов, **завершала генерацию до создания объектов** и делала `force.chart` для всех сил. Теперь это же выполняется при перестройке карты; каждые **180 тиков** повторяются проверка и разведка всей центральной области, как в оригинале. Дополнительная построчная разведка камеры остаётся для дальних модовых планет. Первый запуск/перегенерация из-за синхронной генерации ~35×35 чанков может занять время — это компромисс ради полного открытия без пропадающих при создании сущностей.
- Исправлена регрессия неподвижных орбит после удаления кнопки паузы: при обновлении очищаются сохранившиеся `paused=true` и `time_scale=0`. Солнце сохраняет картинку entity, дополненную свечением/ядром из старого проекта для видимости; если создание любого тела не удалось, оно повторяется после генерации чанка и ошибка пишется в лог. Платформы за старой границей догенерируют недостающий чанк; ошибка создания платформы логируется не чаще раза в 600 тиков.
- `/dsm-hover-debug` теперь показывает количество тел, наличие солнца, платформы, часы, скорость и паузу — **только по явному вызову**. Это поможет понять дальнейшие неполадки в реальном клиенте. Боковая панель и кнопка из 0.17.0 не возвращены, Shift+M сохранено.
- Модельные тесты проверяют полную генерацию **перед** размещением маркеров, повторную разведку, отсутствие новых радаров и восстановление движения после старой паузы. Здесь **нет клиента Factorio**: без проверки в игре нельзя подтвердить ни визуальный результат, ни отсутствие временного тумана у `LuaForce.chart`.

## Полная прогрузка старой области и упрощение интерфейса 0.17.0 (заменено в 0.17.1)

- За основу взята `chart_surface_as_radar` из [старого проекта](https://github.com/ArkadiPorovozov/custom-starmap/blob/117d14ca09a884a83ed055ac020485eb175ca45a/control/surface.lua): центральная область **−500…+500 тайлов** (радиус 16 чанков) запрашивается целиком при создании/перестройке карты и один раз открывается для каждой силы. Генерация внешних чанков идёт **асинхронно**, чтобы не останавливать игру разовой генерацией тысячи чанков. `on_chunk_generated` продолжает открывать готовые чанки.
- В старом проекте повторный полный `chart` запускался каждые 180 тиков, но `LuaForce.chart` не удерживает постоянную видимость и обходить все чанки многократно дорого. Здесь на центре карты постоянно стоит **невидимый работающий радар для каждой силы**: он обеспечивает постоянный обзор всей старой области, даже когда карта закрыта. Раз в 180 тиков проверяется его наличие; только если радар пока невозможно создать, выполняется резервное открытие квадрата. Подвижный радар камеры оставлен для дальних участков модовых систем. Чанки вне старой области генерируются по мере просмотра/движения объектов; вся бесконечная поверхность заранее не создаётся.
- Удалены кнопка быстрого доступа (shortcut) и боковая панель карты со списком, паузой и кнопкой закрытия. Открытие/закрытие — **Shift+M** (или Ctrl+Shift+M); сохранены собственные подсказки планет, окно условий при наведении, информация платформ и управление через runtime API (`focus`, `set_paused`, `regenerate`, `restore`). Старые панели удаляются при обновлении/открытии.
- Прогнаны проверки Lua-синтаксиса, data stage и модельные тесты постоянного радара, асинхронной заявки чанков, пересоздания/очистки и отсутствия sidebar/shortcut. **Фактическая работа и загрузка в Factorio 2.1.21 здесь не подтверждены.**

## Исправление загрузки радара 0.16.9

- Удалён недопустимый для прототипа entity флаг `hidden`, из-за которого Factorio отклонял `dsm-camera-radar` при загрузке 0.16.8. Невидимость по-прежнему обеспечивается прозрачным спрайтом, пустой коллизией, `selectable_in_game=false` и разрешённым флагом `not-on-map`. Добавлен модельный тест допустимых флагов радара.
- **Работа в клиенте Factorio после исправления ещё не подтверждена**: модельные тесты не могут гарантировать успешную загрузку игры и постоянный обзор.

## Постоянный обзор от настоящего радара 0.16.8

- Исправлена проблема, когда временная разведка `LuaForce.chart` исчезала через некоторое время: у каждого игрока **при открытой карте** создаётся собственный невидимый `dsm-camera-radar` его силы. Он работает от `void`-источника без энергосети и постоянно показывает окружающие камеру чанки в радиусе **16 чанков** (в пределах сгенерированной области). При перелёте камеры в другой чанк радар перемещается за ней. Иные поверхности и чужие remote-view камеры модовым радаром не затрагиваются.
- Центральные чанки открываются сразу, остальная область генерируется асинхронно. Пока новый чанк не сгенерирован и радар нельзя установить, действует запасная построчная `chart`-разведка; после установки радара постоянные построчные вызовы отключаются, чтобы снизить нагрузку. Когда игрок закрывает карту, покидает её, удаляется или карта пересоздаётся, радар уничтожается. При закрытой карте постоянный обзор за бывшей камерой **не поддерживается**.
- Проверены Lua-синтаксис, data-stage модель прототипа и модельные тесты открытия, следования за камерой, ожидания генерации, запасного сканирования и очистки. **В настоящем клиенте Factorio 2.1.21 работу радара ещё необходимо проверить.** Предыдущие архивы не перезаписаны.

## ЛКМ по объектам и плавное движение 0.16.7

- **ЛКМ по планете или платформе:** обработчик клика теперь определяет цель по `event.cursor_position` и актуальным `LuaEntity.selection_box` в мировых координатах, даже если `player.selected` ещё содержит прошлый объект или равен `nil` на момент custom-input. При нескольких кандидатах выбирается ближайший собственный маркер; интерфейсные окна не перехватываются. Клик по пустому месту не переносит камеру. ПКМ использует тот же поиск для перехода на доступную реальную поверхность.
- **Плавное движение во время просмотра карты:** спрайты планет, лун, стоящих/летящих платформ, подписи и центры лунных орбит теперь обновляются при каждом даже малом сдвиге, без прежнего визуального порога `0.01` тайла. Реальные entity для выделения подтягиваются к изображению с допуском менее `0.003` тайла, чтобы не телепортировать их ради каждого микросдвига. Без зрителей прежняя оптимизация порогов остаётся. Направления спрайтов также обновляются плавнее.
- `/dsm-hover-debug` в логе дополнительно показывает последнее событие ЛКМ, найденную цель и координаты курсора; обычные клики по-прежнему не печатают сообщения. Модельные тесты проверяют ЛКМ без выбранной entity, устаревший `player.selected`, пустое место, платформы и малые шаги движения. **В реальном клиенте Factorio ещё не проверено.**
- Исходники в `/home/user/dynamic-starmap`; новая версия архивируется в `/home/user/backups` вместе с предыдущими.

## Временная построчная разведка 0.16.6 (заменена настоящим радаром в 0.16.8)

- Во время просмотра звёздной карты чанки вокруг **камеры** запрашиваются при переходе в новый чанк или смене зума, с запасом по краям видимой области. Большой радиус генерируется асинхронно; при открытии/фокусировке немедленно генерируется только центр. Таким образом, панорамирование не запускает дорогую синхронную генерацию всего экрана.
- Разведка области камеры теперь **обновляется каждый тик даже при неподвижной камере**: за тик сканируется одна полоса высотой один чанк. Полный проход при максимальном радиусе 16 чанков занимает не более 33 тиков; этот механизм задумывался для обновления картинки, но `chart` не обеспечивал постоянную видимость: в 0.16.8 при работающем радаре построчное сканирование отключено. При переносе камеры новая центральная область раскрывается немедленно, а периферия последовательно сканируется.
- Даже когда никто не смотрит на карту, один небесный объект за тик вместе с прилегающими 32 тайлами повторно разведуется **для каждой силы**. Уже сгенерированные чанки не стираются; новые у тел по-прежнему запрашиваются асинхронно. Это **не генерация бесконечной поверхности целиком**, а непрерывная радарная разведка вокруг камеры и тел.
- Модельные тесты проверяют повторное обновление неподвижной камеры, полный цикл сканирования, отсутствие повторной генерации чанков и разведку тел без зрителей. В клиенте Factorio результат ещё не проверен.

Летящая платформа по-прежнему останавливается до границы планеты, теперь учитывая новый отступ `0.32` тайла; расположение парковочных колец не менялось.

## Наведение без рамки, диагностика и радиус стоянки 0.16.3

- Выбран режим **без рамки**, а не нативное выделение: планеты остаются `selectable_in_game=false`, поэтому `player.selected` при наведении на них не устанавливается. Factorio 2.1 не позволяет скрыть штатную рамку, сохранив обычную область нативного выделения; пустой `selection_box` также отключает выбор. Это сознательный компромисс, выбранный для карты.
- Откатил экспериментальные GUI-кнопки и их стиль `dsm_invisible_hit`. Вновь используются простые `empty-widget` для наведения; **ЛКМ** и **ПКМ** обрабатываются отдельными `custom-input` для кнопок мыши (`dsm-focus-target` и `dsm-remote-target`), по `event.element` над невидимой зоной. Обычные кнопки меню не перехватываются. Координаты зон при отличном от 100% масштабе интерфейса исправлены ранее и сохранены. Проверка в самом клиенте Factorio всё ещё необходима.

## Надёжное наведение 0.11.0

В старом `custom-starmap` персонаж **переносился** на карту. Его `on_selected_entity_changed` сохранял имя маркера во временном hover-пробнике, а окно обновлялось из пробника каждый тик. В этом моде персонаж остаётся на прежней поверхности, а карта открывается в Remote View: рассчитывать **только** на `player.selected` и событие выделения здесь было ошибкой. Поэтому прошлое исправление маркера не обеспечило появление меню.

Также, как в старом проекте, сама entity-маркер получает собранный в data stage `localised_description`: описание, поля, условия, ресурсы и конечный радиус орбиты. До 0.15.0 это была также штатная подсказка движка; после отключения выделения планет при наведении на карту используется только собственное меню, а описание остаётся в прототипе для совместимости.

Теперь для **каждой видимой планеты, луны и локации** на экране камеры создаётся невидимый `empty-widget` (в 0.16.1–0.16.2 временно была прозрачная кнопка) над её изображением. Он перемещается вместе с планетой и камерой, меняет размер при зуме и независимо от выделения entity отправляет `on_gui_hover`/`on_gui_leave`. То же окно с данными из data stage открывается по этому событию и остаётся видимым, пока курсор над телом. Старый путь `player.selected` в коде остаётся как резервный для внешнего API, но маркеры планет с 0.15.0 больше не выбираются движком. Панель управления выводится поверх невидимых зон; зоны удаляются при закрытии карты. Невидимые зоны не создают новые тела или маршруты.

При ошибке в дополнительном оформлении меню теперь остаётся хотя бы базовая карточка с названием и условиями; ошибка записывается в лог как `[dynamic-starmap] hover menu:`. Если окно всё-таки не откроется в клиенте, после наведения выполните `/dsm-hover-debug`: строка появится в чате и `factorio-current.log` и покажет количество активных экранных зон, последнее GUI- и entity-наведение и открытую карточку без сообщений в чате. **В реальном клиенте Factorio результат ещё не проверен**; модельные проверки подтверждают создание зон и открытие карточки даже с `player.selected=nil`.

## Исправления 0.10.0

- **Прогрузка привязана к камере каждого игрока на `dsm-space`.** При входе, перемещении камеры на новый чанк и изменении масштаба мод рассчитывает видимую область по разрешению экрана и `player.zoom`, генерирует её с запасом в два чанка и сразу открывает для силы игрока. Размер области ограничен для защиты от слишком далёкого зума. Уже сгенерированные чанки и разведка не удаляются; планеты вне камеры по-прежнему получают минимальную генерацию для своих entity. Это работает и для чужой камеры, направленной на нашу поверхность.
- **Маркерные entity (до 0.15.0):** у прозрачных маркеров планет, солнца и платформ было явно задано `selectable_in_game=true`. Теперь у планет и солнца оно отключено во избежание рамки выделения, а GUI-зоны стали основным способом наведения и ЛКМ-фокуса. Меню остаётся рядом с движущимся телом, показывая data-stage сведения и о ещё не исследованных планетах; доступ к переходу на поверхность по-прежнему проверяется отдельно.
- **Лунные кольца меньше:** после прибавки 5 к исходным промежуткам их автоматические радиусы умножаются на `moon_scale=0.6`. Для API-радиусов, явно заданных через `Map:update`, этот множитель не применяется. Радиусы обычных планет не меняются.
- Названия платформ находятся **над** их значками (`−0.43` тайла), а названия планет придвинуты ближе к изображениям (зазор `0.16` вместо `0.5` тайла); положения обновляются вместе с объектами.

## Интервалы и меню 0.9.0

- **Расстояния берутся непосредственно из data stage.** Для каждого набора планет или лун вокруг общего родителя тела упорядочиваются по финальному `distance` (либо `orbit.distance` PlanetsLib). К **каждому промежутку** от родителя до первого тела и между соседними телами прибавляется ровно **5 тайлов**. Например, исходные радиусы 10, 15, 20, 25, 35 превращаются в **15, 25, 35, 45, 60** для планет: исходные интервалы 10, 5, 5, 5, 10 становятся 15, 10, 10, 10, 15. Лунные радиусы затем уменьшаются множителем 0.6 в 0.10.0. Нелинейное растяжение из 0.8.0 **удалено**, стандартный `distance_multiplier` теперь **1**, `orbit_gap=5`. Дополнительный отступ применяется только при угрозе перекрытия спрайтов. Радиусы, явно указанные через `Map:update{name="...",radius=...}`, остаются точными и не получают +5; параметр `distance_multiplier` можно поменять через API, если нужно масштабировать всю карту.
- **При наведении открывается своё меню в стиле `tooltip_frame`**, вслед за движущейся планетой: название, картинка, описание (включая локализационный fallback), пользовательские поля подсказки, свойства поверхности с единицами измерения, радиус на карте, солнечная энергия и иконки ресурсов/флоры/угроз с подписями. Значения, описания и перечни содержимого собраны из конечных прототипов в `data-final-fixes.lua`; в runtime читается готовый каталог, а live-прототипы используются только для локализованных названий/иконок. Окно исчезает после ухода курсора; просмотр сведений доступен и у ещё не исследованных планет, но переход на них требует открытия локации. Использованы структура старого `custom-starmap` и его поведение привязки подсказки к телу, без изменения маршрутов.

## Исправления 0.7.0

- **Солнце и обычные орбиты восстановлены.** В стандартной Space Age солнце изображается штатным `utility-sprites.default.starmap_star`, но отдельный `space-location` с именем `star` может отсутствовать. Теперь карта **всегда создаёт собственный центральный entity-узел** `dsm-node-star` с картинкой штатного солнца; новый реальный `space-location` и космический маршрут при этом не создаются. Планеты без другого родителя обращаются вокруг этого центра, поэтому обычные кольца снова рисуются. На нашей отдельной поверхности орбиты отображаются даже если `draw_orbit=false` в ванильной *плоской* карте; скрыть конкретное кольцо можно только явным `Map:update{name="...",draw_orbit=false}`. Орбиты лун тоже сохраняются; цвета колец сделаны заметнее на тёмном космическом фоне.
- **Размеры изображений и рамок выбора теперь следуют `magnitude`** конечных прототипов: до общего уменьшения в 0.14.0 видимый диаметр равнялся `2 * magnitude` тайла; теперь результат дополнительно умножается на `2/3`. Убраны постоянная добавка и безусловное уменьшение лун вдвое; рамка выбора использует тот же размер (обводка тела удалена в 0.13.0). Если `magnitude` не задано, запасной диаметр составляет `2.2` тайла для планеты и `1` тайл для луны. Это *видимый размер на карте Factorio*, не физический диаметр небесного тела; `Map:update{name="...",size=...}` по-прежнему имеет приоритет.
- **`/dsm-restore`** (администратор или серверная консоль) создаёт заново удалённую `dsm-space` и восстанавливает все объекты, орбиты и разведку. Если поверхность сохранилась, пересобирает объекты на ней **без очистки её чанков**. Есть `remote.call("dynamic_starmap","restore")` → `true` или `false`. Это не то же, что разрушающая `/dsm-regenerate`.

## Ранние изменения 0.6.0 (история)

- **Ванильное солнце.** Entity `dsm-node-star` теперь использует прямо в `picture` изображение игры `__core__/graphics/icons/starmap-star.png` (512 px). Локальный `graphics/sun.png` удалён; отдельного `rendering` для самого солнца нет.
- **Радиусы из реальных данных.** Орбиты строятся из `distance` планет/локаций и `orbit.distance` PlanetsLib. Убраны общий бонус к звёздным радиусам и прежнее сжатие лун до 15%. По умолчанию `moon_scale=0.6`; теперь интервалы между родственными кольцами берутся из data и увеличиваются на 5 тайлов, а при реальном перекрытии раздвигаются дополнительно. С тех пор стандартный множитель изменён на `distance_multiplier=1` в 0.9.0. Служебная скрытая `space-location-unknown` больше не занимает отдельное кольцо. Явный `Map:update{name=...,radius=...}` не подвергается автоматической раздвижке, но тоже умножается на `distance_multiplier`.
- **Вернулись орбиты лун.** Они рисуются вокруг движущегося родителя даже тогда, когда ванильный `draw_orbit=false` скрывает кольцо плоской карты Space Age. Луна может определяться через `orbit.parent` PlanetsLib либо нативный `origin` Factorio 2.1.20+. Для конкретной луны кольцо можно явно выключить `Map:update{name="...",draw_orbit=false}`.
- **Планеты стали медленнее.** Стандартный период выводится из **конечного радиуса**: ориентир `planet_angular_speed=0.00001` радиан/тик на 100 тайлах, скорость зависит от радиуса в степени −0.75. Луны используют `moon_angular_speed=0.00022` радиан/тик. Если задано `period` через API, оно имеет приоритет; `time_scale` и пауза работают как прежде.
- **Приливная синхронизация с солнцем.** Изображение каждого движущегося тела, в том числе луны, поворачивается по его мировому направлению **к солнцу** каждый тик: одна и та же сторона спрайта всегда обращена к нему. Это синхронное вращение, а не неподвижность планеты на орбите. Отдельный параметр `spin` в этом режиме игнорируется; сторонний мод может вернуть независимое вращение для конкретного тела с `tidal_lock=false`.
- **GUI условий по образцу старого проекта.** При наведении на планету появляется `tooltip_frame` рядом с ней: локализованные название и описание, поверхностные свойства (включая значения по умолчанию из прототипов и свойства других модов), условия с единицами измерения, иконки ресурсов/флоры/угроз, солнечная энергия. **Shift+I** переключает карточки свойств непосредственно около планет; карточки следуют за движением и меняют сторону экрана вместе с планетой. Список содержимого рассчитывается на стадии данных. Проверка исследования выполняется для силы каждого зрителя.

## Сохранённое поведение

- **Shift+M** / Ctrl+Shift+M открывают/закрывают карту в Remote View без телепортации персонажа. **ЛКМ** центрирует камеру карты на планете или платформе; **ПКМ** переходит на доступную поверхность; у платформ есть маркеры и камера предпросмотра. Список тел и подробная боковая панель при выборе через список остались.
- Космический тайл `empty-space` генерируется как основной, без перекраски чанков. Вечный день; раскрытие сгенерированных чанков всем силам. При просмотре движение обновляется каждый тик (до 60/с при 60 UPS), вне просмотра реже.
- **Линии путей отсутствуют.** Мод не добавляет, не удаляет, не перестраивает и не переопределяет `space-connection`. Список `get_routes()` — справочные данные о *существующих* соединениях, а не отрисовка. Летящие платформы движутся как маркеры по прямой между конечными точками своего реального соединения.
- `/dsm-regenerate` полностью пересобирает **только** поверхность `dsm-space`: её чанки, объекты, разведку и рисунки, сбрасывая время. Команда доступна администратору и серверной консоли; физический игрок или чужая камера на этой поверхности блокируют очистку. `remote.regenerate()` не проверяет права вызывающего мода. `remote.rebuild()` обновляет собственные entity/rendering, **не** удаляя чанки.

## Установка

Скопируйте папку `dynamic-starmap` в `mods` (для распакованного мода Factorio обычно требуется название `dynamic-starmap_0.16.7`). Удалите старые копии этого мода, чтобы игра не загрузила другую версию. **ZIP не создаётся.** Нужны Factorio **2.1.21** и Space Age; PlanetsLib необязателен. Одновременно включать старый `space-map-rework` не нужно: его сочетания клавиш совпадают, и он меняет ванильные маршруты. Версия повышена для `on_configuration_changed`: на существующем сейве карта пересоберёт свои объекты и орбиты. Если хотите очистить уже сгенерированные дальние чанки предыдущих версий, используйте `/dsm-regenerate`.

## API стадии данных

Из мода с зависимостью от `dynamic-starmap`, в `data.lua`/`data-updates.lua`:

```lua
local Map = require("__dynamic-starmap__/api")
Map:extend{name="nauvis",parent="star",radius=15,phase=0.25,
           size=2.4} -- явно заданный радиус: ровно 15, без прибавки 5
Map:update{name="my-moon",parent="nauvis",radius=4,draw_orbit=true}
Map:configure{scale=1,distance_multiplier=1,moon_scale=0.6,orbit_gap=5,
  planet_angular_speed=0.00001,moon_angular_speed=0.00022,
  update_ticks_active=1,show_platforms=true,
  body_size_multiplier=2/3,orbit_color={r=0.3,g=0.3,b=0.3,a=1}}
```

`extend(node | {node,...})` задаёт настройки **существующих** `planet`/`space-location` (повторное имя — ошибка); `update(...)` меняет отдельные поля. Поля узла: `parent`, `radius`, `phase`, `period`, `orbit_direction`, `spin_direction`, `spin`, `tidal_lock`, `static_picture`, `size`, `color`, `icon`, `icon_size`, `contents`, `draw_orbit`, `hidden`. `period` и `spin` — тики полного оборота, `0` останавливает соответствующее движение; `spin` применяется только при `tidal_lock=false`. `configure` также поддерживает `body_size_multiplier` (применяется ко всем телам кроме солнца после индивидуального `size`), `orbit_color` (общий цвет поверх индивидуальных, `false` возвращает цвета узлов), `static_planet_entities`, `orbit_clearance`, `stars`, `default_size`, `chart_radius`, `time_scale`, `update_ticks`. Старые `orbit_spread`, `orbit_spread_reference`, `orbit_spread_cap` более не используются. В прототипы Space Age/PlanetsLib эти настройки не записываются. Старые `star_bonus`, `star_radius`, `Map:connect()` и настройки визуальных маршрутов больше не используются.

Данные читаются в `data-final-fixes.lua` из финальных прототипов `planet`, `space-location` и справочно `space-connection`, затем передаются в runtime через `prototypes.mod_data["dsm-catalog"].data`. Никакой runtime-код не обращается к `data.raw`.

## Runtime API

Полный справочник методов и примеры интеграции: **[API.md](API.md)**. Таблица ниже — краткая сводка прежнего интерфейса.

| `remote.call("dynamic_starmap", method, ...)` | Действие |
|---|---|
| `get_catalog()`, `get_node(name)`, `get_routes()` | Копии каталога, узла, перечня реальных соединений. |
| `get_platform_marks()` | Копия позиций маркеров платформ по ключу `forceIndex:platformIndex`. |
| `get_surface()`, `get_entity(name)` | Поверхность и entity планеты либо `nil`. Проверяйте `.valid`. |
| `get_state()` | Состояние, включая время, паузу, зрителей и ожидающую очистку. |
| `open(index)`, `close(index)`, `focus(index,name)` | Управление просмотром; `focus` проверяет доступность локации. |
| `rebuild()`, `restore()`, `regenerate()` | Пересборка объектов; создание/починка удалённой поверхности; полная очистка. |
| `set_paused(bool)`, `set_time_scale(0..100)` | Пауза и скорость анимации. |

## Файлы и проверка
